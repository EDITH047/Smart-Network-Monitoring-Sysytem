Project Scope

This system provides a unified dashboard for monitoring network devices, detecting security threats, managing bandwidth, and generating alerts. It follows a 3-tier layered architecture — Presentation (Swing), Business Logic (Services), and Data Access (JDBC/MySQL).

Key Capabilities

Network MonitoringTrack device status, bandwidth, latency, and packet stats in real time
SecurityDetect intrusions, flag anomalies, manage firewall rules, log security events
OptimizationAnalyze traffic patterns, recommend bandwidth allocation, QoS suggestions
Alerts & ReportsThreshold-based alerts, email notifications, exportable reports
User ManagementRole-based access (Admin / Operator / Viewer) with login and audit logging

How Data Flows Through the System

1. User Login Flow

1
User enters credentials in LoginFrame
2
AuthService.login() hashes password using PasswordUtil
3
UserDAO.findByUsername() runs PreparedStatement against MySQL
4
If matched → set session, log to audit_log, open MainDashboard
5
Dashboard tabs restricted based on user role (ADMIN sees all, VIEWER sees read-only)

2. Network Monitoring Flow

1
javax.swing.Timer triggers every N seconds in MonitoringPanel
2
MonitoringService.collectMetrics() gathers data (simulated random + InetAddress.isReachable)
3
NetworkMetricDAO.insertMetric() persists to MySQL via JDBC PreparedStatement
4
AlertService.checkThresholds() evaluates if bandwidth > 90%, latency > 200ms, etc.
5
If threshold breached → insert into alerts table, update alert badge on dashboard
6
MonitoringPanel JTable refreshes with new data, chart redraws

3. Security Threat Detection Flow

1
Each new metric is also passed to SecurityService.analyze()
2
Checks: packet rate spike (DDoS), repeated failed connections (Brute Force), unusual port access (Port Scan)
3
If threat detected → SecurityEventDAO.insertEvent() with type, severity, source IP
4
Critical threats auto-add source IP to blocked_ips via BlockedIPDAO
5
SecurityPanel table updates, AlertPanel shows CRITICAL notification

4. Optimization Analysis Flow

1
User clicks "Run Optimization" on OptimizationPanel
2
OptimizationService.analyze() queries last 24 hrs of metrics per device
3
Calculates avg usage, peak times, underutilized vs overutilized devices
4
Generates recommendations: "Reallocate 20Mbps from Device A to Device B"
5
Saves to optimization_results table with score (0–100)

JDBC Usage Throughout

Every database interaction uses JDBC PreparedStatement to prevent SQL injection. The pattern across all DAOs:

// Typical DAO method pattern public List<Device> getAllDevices() { String sql = "SELECT * FROM devices ORDER BY device_name"; List<Device> devices = new ArrayList<>(); try (Connection conn = DatabaseConfig.getConnection(); PreparedStatement ps = conn.prepareStatement(sql); ResultSet rs = ps.executeQuery()) { while (rs.next()) { Device d = new Device(); d.setDeviceId(rs.getInt("device_id")); d.setDeviceName(rs.getString("device_name")); d.setIpAddress(rs.getString("ip_address")); // ... map remaining columns devices.add(d); } } catch (SQLException e) { e.printStackTrace(); } return devices; }

Database Connection Setup

// DatabaseConfig.java — Singleton JDBC Connection Manager public class DatabaseConfig { private static final String URL = "jdbc:mysql://localhost:3306/network_monitor_db"; private static final String USER = "root"; private static final String PASSWORD = "your_password"; private static Connection connection; public static Connection getConnection() throws SQLException { if (connection == null || connection.isClosed()) { try { Class.forName("com.mysql.cj.jdbc.Driver"); connection = DriverManager.getConnection(URL, USER, PASSWORD); } catch (ClassNotFoundException e) { throw new SQLException("MySQL Driver not found", e); } } return connection; } public static void closeConnection() { try { if (connection != null) connection.close(); } catch (SQLException e) { e.printStackTrace(); } } }
